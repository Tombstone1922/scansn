# ScanSN

Нативное Android-приложение для учёта телефонов, планшетов и комплектующих ПК со сканированием штрихкодов и аккуратной выгрузкой в Excel / Google Таблицы.

## Возможности

- сканирование SN, IMEI и номера заказа камерой (ML Kit, работает на устройстве);
- анализ 1920×1080 для узких штрихкодов, фокус по касанию, pinch-to-zoom, ползунок масштаба и фонарик;
- принимаются только коды внутри реальной рамки с учётом поворота и FILL_CENTER; ближайший к центру код имеет приоритет;
- все значения подтверждаются на нескольких последовательных кадрах; IMEI дополнительно проверяется по 15 цифрам и контрольной цифре Luhn;
- генерация штрихкодов Code 128 для SN, IMEI и номера заказа из карточки товара;
- отдельный набор полей для телефона, планшета и комплектующего ПК;
- офлайн-каталог из 2 498 моделей, включая устройства 2024–2026 годов, подсказки из истории и свободный ручной ввод;
- 12 подкатегорий комплектующих с фильтрацией брендов и моделей;
- площадка, цвет, аккаунт, цена, пошлина и комментарий;
- локальная Room-база, поиск и фильтры, проверка повторных SN/IMEI;
- копирование всех записей в TSV для вставки на лист;
- экспорт CSV (UTF-8) и оформленного XLSX без стороннего сервера;
- отдельные листы «Товары» и «Штрихкоды» в XLSX, закреплённые заголовки, фильтры, границы и изображения Code 128;
- длинные цифровые коды сохраняются как текст, без округления Excel;
- проверка обновлений в приложении, загрузка APK с GitHub Releases и проверка SHA-256 перед передачей системному установщику Android.

## Поля таблицы

Площадка; тип товара; подкатегория; бренд; модель; цвет; аккаунт; цена; таможенная пошлина; SN; IMEI; номер заказа; комментарий; дата изменения. Ссылка на товар специально не используется.

Для телефона обязательны SN, IMEI и заказ. Для планшета IMEI необязателен. Для комплектующих нужны SN и заказ.

Штрихкоды создаются локально в формате Code 128. Значения с символами вне ASCII остаются в таблице как текст; вместо некорректного изображения приложение показывает предупреждение.

## Запуск

1. Откройте проект в Android Studio с JDK 17 и Android SDK 34 и Build Tools 35.
2. Дождитесь синхронизации Gradle.
3. Запустите приложение на устройстве Android 8.0 (API 26) или новее и разрешите доступ к камере.

Проверка из командной строки:

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.

## CI/CD и обновления

`Android CI` запускается для push в `main` и pull request: unit-тесты, lint, debug-сборка и APK-артефакт.

`Android Release CD` запускается по тегу `v*`, собирает подписанный release APK, проверяет его подпись и публикует GitHub Release. Вместе с APK публикуются:
- `latest.json` — версия, versionCode, ссылка на APK и SHA-256;
- `checksums.txt` — контрольная сумма APK.

В приложении откройте значок обновления на главном экране и нажмите «Проверить обновления». Если доступна новая версия, приложение скачает APK с GitHub Releases, сверит SHA-256 и откроет системный установщик Android. Пользователь должен разрешить установку приложений из этого источника (если Android запросит разрешение) и подтвердить обновление. Тихая установка не выполняется. Для обновления поверх установленной версии необходимо сохранять тот же ключ подписи.

В **Settings → Secrets and variables → Actions** нужны секреты:

- `ANDROID_KEYSTORE_BASE64` — keystore в Base64;
- `ANDROID_KEYSTORE_PASSWORD`;
- `ANDROID_KEY_ALIAS`;
- `ANDROID_KEY_PASSWORD`.

Keystore и его пароли не входят в репозиторий.

## Данные

Все товары хранятся локально в `scansn.db`; интернет для сканирования, генерации штрихкодов и экспорта не нужен. База включена в штатное резервное копирование Android. Экспортируемые файлы создаются через системный диалог сохранения.

Каталог находится в `app/src/main/assets/catalog.json`. Для повторного применения набора моделей 2024–2026 годов используется `python tools/expand_catalog.py`; существующие модели сохраняются, дубликаты удаляются. Источники обновления указаны в самом JSON.
